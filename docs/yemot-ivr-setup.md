# יצירת משימה דרך הטלפון — ימות המשיח (Yemot Hamashiach)

מנגנון זה מאפשר ליצור משימה במערכת בט"ל באמצעות שיחה קולית בקו ימות המשיח.
השיחה מחולקת לשדות, וכל נתון נשמר בשדה המתאים בטבלת המשימות הקיימת (`tasks`).

## איך זה עובד (סקירה)

הזרימה כולה מנוהלת על ידי **שלוחת API אחת** בימות המשיח. בכל שלב ימות המשיח
פונה לכתובת השרת שלנו, והשרת מחזיר את ההנחיה הבאה (השמעה / הקלטה / הקשה).
מצב השיחה נשמר זמנית בטבלת `ivr_sessions`, והמשימה נכתבת ל-`tasks` **רק** לאחר
שהמשתמשת מאשרת (הקשה 1). ניתוק לפני אישור לא יוצר משימה חלקית. מזהה השיחה
הייחודי (`ApiCallId`) מונע כפילויות.

הכתובת (Endpoint):

```
https://<הדומיין-שלך>/api/ivr/yemot?token=<YEMOT_IVR_TOKEN>
```

## הגדרת השלוחה בימות המשיח

1. היכנסי לניהול המערכת בימות המשיח → **ניהול שלוחות**.
2. צרי שלוחה חדשה (למשל `5` — "פתיחת משימה").
3. בהגדרות השלוחה בחרי סוג שלוחה: **שלוחת API / ממשק API** (`api`).
4. בשדה כתובת ה-API הזיני את ה-Endpoint כולל ה-`token`:
   ```
   https://<הדומיין-שלך>/api/ivr/yemot?token=<YEMOT_IVR_TOKEN>
   ```
5. שיטת הבקשה: `GET` או `POST` — שתיהן נתמכות.
6. ודאי ש"העברת משתני שיחה" פעילה (ברירת המחדל) כך שימות מחזיר את ערכי
   ההקלטות/ההקשות בכל פנייה.

> השרת מנהל את כל סדר השלוחות באופן לוגי. אין צורך להגדיר ידנית שלוחות נפרדות
> לכל שלב — שלוחת ה-API האחת מספיקה. השלבים הלוגיים שהשרת מפעיל הם:

| שלב | תיאור | סוג קלט |
|-----|-------|---------|
| פתיחה | "להקלטת משימה חדשה הקישי 1" | הקשה (1) |
| כותרת | "הקליטי בקצרה את כותרת המשימה ולסיום הקישי סולמית" | הקלטה |
| תיאור | "הקליטי פרטים נוספים... אם אין, הקישי סולמית" | הקלטה |
| תאריך יעד | היום / מחר / בחירה ידנית / ללא | הקשה (1-4) |
| בחירת תאריך | "יום חודש שנה — 8 ספרות" | הקשה (8 ספרות) |
| שעת יעד | הקלדת שעה / ללא שעה | הקשה (1-2) |
| הקלדת שעה | "שעות ודקות — 4 ספרות" | הקשה (4 ספרות) |
| עדיפות | רגילה / גבוהה / דחופה | הקשה (1-3) |
| שיוך | ללא שיוך / שיוך לתיק קיים | הקשה (1-2) |
| בחירת מטופלת | מספר מזהה או טלפון | הקשה + סולמית |
| אישור | סיכום + שמירה (1) / הקלטה מחדש (2) / ביטול (3) | הקשה (1-3) |

## משתני סביבה נדרשים (Vercel → Settings → Environment Variables)

| משתנה | תיאור |
|-------|-------|
| `YEMOT_IVR_TOKEN` | סוד משותף. ימות חייב לשלוח אותו בפרמטר `token`. אם חסר — הנתיב פתוח (לא מומלץ בפרודקשן). |
| `SUPABASE_URL` | כתובת פרויקט ה-Supabase (אפשר ליפול חזרה ל-`NEXT_PUBLIC_SUPABASE_URL`). |
| `SUPABASE_ANON_KEY` | מפתח anon בלבד — **לא** service_role (אפשר ליפול חזרה ל-`NEXT_PUBLIC_SUPABASE_ANON_KEY`). |

## מיגרציה במסד הנתונים

יש להריץ את `migrations/20260618_phone_tasks.sql` ב-SQL Editor של Supabase
(או את `schema.sql` המעודכן). היא:

- מוסיפה לטבלת `tasks` את העמודות: `priority`, `source`, `caller_phone`,
  `recording_url`, `transcription`, `call_external_id` (+ אינדקס ייחודי).
- יוצרת טבלת `ivr_sessions` לאחסון זמני של מצב השיחה.

המיגרציה בטוחה להרצה חוזרת ואינה נוגעת בתשלומים / תיקים / RLS קיימים.

## מיפוי השדות (בקשה ← עמודה בטבלה)

| נתון בשיחה | עמודה ב-`tasks` |
|------------|------------------|
| כותרת | `task_definition` |
| תיאור | `call_details` |
| תאריך יעד | `date_gregorian` |
| שעת יעד | `start_time` |
| עדיפות | `priority` |
| סטטוס | `status` = "פתוח" |

| טלפון מתקשר | `caller_phone` |
| הקלטה | `recording_url` |
| תמלול | `transcription` |
| מזהה שיחה (כפילויות) | `call_external_id` |

## תמלול והקלטות

- אם חשבון ימות מספק תמלול (Speech-to-Text), השרת ישתמש בו לשדות הטקסט.
- אם אין תמלול, הכותרת/התיאור נשמרים כ-placeholder וההקלטה נשמרת
  (`recording_url`) לטיפול ידני. כפתור **"האזנה להקלטה"** מופיע בכרטיס המשימה.
- שיוך מטופלת מתבצע לפי התאמת ספרות הטלפון. אם לא נמצאה התאמה חד-משמעית,
  המשימה נוצרת ללא שיוך והמספר שהוקש נשמר בהערות לטיפול ידני.

## בדיקה ידנית של שיחה מלאה

ניתן לדמות את כל השיחה עם `curl` (כל בקשה מדמה שלב; שמרי על אותו `ApiCallId`):

```bash
BASE="http://localhost:3001/api/ivr/yemot?token=LOCAL_SECRET"
CID="testcall-001"

# 1) פתיחה → מקבלים read של "הקישי 1"
curl -s "$BASE&ApiCallId=$CID&ApiPhone=0501234567"
# 2) הקשה 1 → בקשת הקלטת כותרת
curl -s "$BASE&ApiCallId=$CID&ApiPhone=0501234567&v1_1=1"
# 3) כותרת הוקלטה → בקשת תיאור
curl -s "$BASE&ApiCallId=$CID&v2_1=rec/title.wav"
# 4) דילוג על תיאור → בחירת תאריך
curl -s "$BASE&ApiCallId=$CID&v3_1=0"
# 5) תאריך = היום → שעה
curl -s "$BASE&ApiCallId=$CID&v4_1=1"
# 6) ללא שעה → עדיפות
curl -s "$BASE&ApiCallId=$CID&v6_1=2"
# 7) עדיפות גבוהה → שיוך
curl -s "$BASE&ApiCallId=$CID&v8_1=2"
# 8) ללא שיוך → מסך אישור (סיכום)
curl -s "$BASE&ApiCallId=$CID&v9_1=1"
# 9) אישור ושמירה → "המשימה נשמרה בהצלחה"
curl -s "$BASE&ApiCallId=$CID&v11_1=1"
```

לאחר שלב 9 תיווצר שורה אחת בטבלת `tasks` עם `source='phone'`, והיא תופיע
בממשק ניהול המשימות עם התג "מהטלפון". הרצה חוזרת של שלב 9 עם אותו `ApiCallId`
לא תיצור כפילות (אידמפוטנטיות לפי `call_external_id`).

> שמות המשתנים בפועל (`v<step>_<attempt>`) נקבעים על ידי השרת ומוחזרים בתוך
> פקודות ה-`read`. בשיחה אמיתית ימות המשיח מטפל בהם אוטומטית — אין צורך להגדירם
> ידנית. הדוגמה לעיל היא לבדיקה בלבד.
